# Инструкция по управлению логами (Logging Guide)

В проекте реализована централизованная система логирования, которая позволяет управлять выводом отладочной информации из одного файла и минимизировать влияние на производительность.

## 1. Где находятся настройки
Все управление сосредоточено в файле:
`app/src/main/java/com/p2petrovich/telegramnewsreader/utils/DebugConfig.kt`

## 2. Глобальные настройки (Мастер-флаги)
Эти флаги управляют соответствующими уровнями логирования по всему приложению:

*   `ENABLE_DEBUG_LOGS`: Управляет уровнями `Debug`, `Info` и `Verbose`.
    *   *Примечание:* Работают только в отладочных (Debug) сборках. В релизе отключаются автоматически на уровне компилятора.
*   `ENABLE_WARN_LOGS`: Включает/выключает предупреждения (`Logx.w`).
*   `ENABLE_ERROR_LOGS`: Включает/выключает сообщения об ошибках (`Logx.e`).

## 3. Детальные логи модулей
Ниже в `DebugConfig.kt` расположены специфичные флаги для глубокой отладки:

*   `LOG_PIPELINE_STAGES`: Просмотр текста новостей на этапах загрузки, фильтрации, AI-обработки и подготовки к озвучке.
*   `LOG_TG_HISTORY`: Детальные запросы пагинации в Telegram (ID сообщений, даты, количество).
*   `LOG_DEDUP_DETAILS`: Подробности работы дедупликатора (почему новость была отсеяна).
*   `LOG_PLAYER_EVENTS`: События воспроизведения, прогресс и пометка новостей как прочитанных.

## 4. Как правильно писать логи в коде
Вместо стандартного `android.util.Log` необходимо использовать обертку **`Logx`**.

### Для Debug, Info, Verbose (с использованием лямбды):
Использование `{ }` критически важно — код внутри скобок выполнится только если логи включены.
```kotlin
Logx.d(TAG) { "Результат сложной операции: ${someObject.getDetails()}" }
```

### Для Warning и Error:
Здесь используются обычные строки, так как они должны быть максимально надежными:
```kotlin
Logx.w(TAG, "Предупреждение: сервер вернул код 429")
Logx.e(TAG, "Критическая ошибка", exception)
```

## 5. Типовые сценарии

### "Ничего не работает, новости не грузятся"
1. В `DebugConfig.kt` поставьте `ENABLE_DEBUG_LOGS = true`.
2. Поставьте `LOG_TG_HISTORY = true`.
3. Смотрите в Logcat по тегу `TelegramClient`.

### "AI выдает странный результат или пустые строки"
1. В `DebugConfig.kt` поставьте `LOG_PIPELINE_STAGES = true`.
2. В Logcat ищите теги `AI_IN` (что отправили модели) и `AI_OUT` (что пришло в ответ).

### "Хочу чистый лог без мусора перед релизом"
Просто установите все флаги в `DebugConfig.kt` в значение `false`. Приложение продолжит работать максимально тихо.

---
*Эта система создана для того, чтобы отладка не превращалась в поиск иголки в стоге сена из тысяч строк текста.*
