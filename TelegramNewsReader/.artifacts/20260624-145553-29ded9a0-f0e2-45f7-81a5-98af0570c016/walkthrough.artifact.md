# Результаты исправления системы сбора и фильтрации новостей

В ходе выполнения задачи была полностью переработана логика сбора новостей из Telegram и механизм отсева дубликатов.

## Ключевые изменения

### 1. Стабильность Telegram (`TelegramClient.kt`)
*   **Исправлена пагинация**: Теперь цикл загрузки не обрывается, если Telegram отдал меньше 100 сообщений в одном пакете.
*   **Принудительная синхронизация**: Добавлена пауза 500мс после `OpenChat`, чтобы локальная база TDLib успела подгрузить актуальные данные с сервера.
*   **Начальная точка**: Загрузка теперь всегда начинается с актуального состояния (`msgId = 0`), что гарантирует получение самых свежих новостей.

### 2. Умный Дедупликатор (`Deduplicator.kt`, `MainViewModel.kt`)
*   **Пометка при воспроизведении**: Новости больше не считаются "прочитанными" сразу после сбора. Они попадают в базу дедупликатора только в момент, когда плеер начинает их играть.
*   **Результат**: Если вы собрали 20 новостей, но послушали только 1, то при следующем нажатии "Собрать" остальные 19 останутся в списке.

### 3. Чистота интерфейса (`NewsService.kt`, `TextProcessor.kt`)
*   **Пустые заголовки**: Добавлена функция `dropEmptyHeaders`, которая удаляет названия каналов из плейлиста, если в них не осталось новостей после всех фильтров.
*   **Сброс счетчиков**: Счетчик пропущенных дубликатов теперь обнуляется при каждом новом сборе, не накапливая ошибки прошлых запусков.

### 4. Управление отладкой (`DebugConfig.kt`)
*   Создан единый файл настроек для логов. По умолчанию все "тяжелые" логи (тексты всех новостей на каждом этапе) отключены для экономии ресурсов, но их можно включить одной правкой.

## Подтверждение работы
Анализ логов последней сессии подтвердил:
1. Telegram стабильно отдает полные пакеты сообщений.
2. При начале проигрывания вызывается `markAsRead`.
3. Повторный сбор корректно отсеивает только прослушанную новость, сохраняя остальные уникальные события.

Система готова к повседневному использованию.
